# CI failure labels: conservative addition only

Implementation: `.github/workflows/ci-status-label.yml`, `.github/scripts/add_ci_label.py`, `.github/scripts/ci_label_api.py`, `python/tests/test_ci_status_label.py`, and `docs/ci-status-label.md`.

Schedule/manual only, manual default branch guard, immutable event SHA checkout, no PR checkout or PR code execution. Token is passed only to reviewed default-branch runner; explicit GH_REPO scopes every API request. Existing label is used; no label definition update/force, deletion, closure, merge or approval API. Trusted code must first land on default branch through separate review/authorization; manual runs before that are not deployment evidence.

Enumerates every open PR and all latest checks/statuses. ADD requires completed bad check from GitHub Actions app ID 15368 and slug github-actions, associated workflow run with same repository/head/check_suite_id, completed bad run and resolvable workflow ID/path. Unknown provenance is HOLD. All legacy statuses are read but cannot independently cause ADD without a reviewed creator policy; no invented universal trust list. Pending unrelated jobs do not hide a proven failure. Repeats the complete assessment and final open/head read before POST. No removal implementation or expected-gate inference exists.

Known limits: no GitHub head/label compare-and-swap, so the final read-to-POST race remains; this can conservatively add a stale failure label but can never remove an existing one. Workflow identity proves association, not that arbitrary PR workflow contents are safe to execute (we execute none). Changed/deleted workflow metadata and API errors HOLD. Runtime cost is bounded by 10-minute job timeout and 1000-page ceiling; timeout/API failure never authorizes removal. Label removal is not automated. A human maintainer may remove the label after verifying that all applicable required gates succeeded for the latest PR head; empty, skipped, partial or stale checks are not sufficient. Required-gate policy must be reviewed separately before automatic removal is considered. Offline tests do not establish live API execution or writer validation.

Offline: python3 -B -m unittest discover -s python/tests -p test_ci_status_label.py -v; actionlint .github/workflows/ci-status-label.yml. Mock tests cover known Actions evidence, producer/repo/head/suite/workflow mismatches, rerun/head races, pagination/truncation/foreign links, legacy-only failures and API errors. No network or label writes during tests.

Permission delta: adds `actions: read` to authenticate workflow/run identity; reduces `pull-requests: write` to `read`; retains `checks: read`, `contents: read`, and `issues: write` for observation, trusted default-branch checkout, and label addition respectively. Checkout uses the repository-reviewed v7 SHA, not a new action version.
